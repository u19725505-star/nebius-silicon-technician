# Silicon Technician

An AI data center technician co-pilot. It reads server telemetry the way a floor technician does, decides what is wrong, tells a human what to check, and takes only guarded, safe actions. Built for the Nebius x NVIDIA Global AI Hackathon with NVIDIA Nemotron served through Nebius Token Factory.

**Live demo:** https://silicon-technician-judge-api.onrender.com
The free hosting tier sleeps when idle, so the first load can take up to a minute. The hosted site reports which model it is using at /health.

## What is real and what is simulated

| Part | Status |
|---|---|
| Nemotron diagnosis calls | Real, through Nebius Token Factory |
| Host processor measurements (CPU use, scheduler delay) | Real, read from the machine running the code |
| Server management controller (BMC) | Emulated: standard Redfish-shaped data, no real server connected |
| Fault cases in the benchmark | Generated by our own simulator |
| Robot, rack scene and visual markers in the Mission Lab | Simulation. There is no live camera and no physical robot |

## The problem

Fixed-threshold monitoring misses mild faults, raises false alarms on sensor glitches, and cannot tell a runaway process from a scheduled job. A technician compares cores with their peers, ignores impossible readings, and checks the maintenance schedule. Silicon Technician gives Nemotron that same context, then checks its answers in code.

## Results

| Test set (never used to tune the prompt unless noted) | Fixed rules | Nemotron Ultra |
|---|---|---|
| 20 cases, seed 777 | 6/20 | 20/20 (Super 19, Nano 16) |
| 60 cases, seed 2026 (prompt v2) | 17/60 | 57/60 (Super 53/60) |
| 60 cases, seed 3031 (prompt v3, fresh) | 20/60 | 60/60 |

Ultra median time per diagnosis was 5.4 seconds on the fresh set. At listed Token Factory prices our estimate is well under one cent per diagnosis. Raw files are in the repository: bakeoff_results.txt, bakeoff_n60.txt, bakeoff_n60_seed3031.txt and bakeoff_ultra.txt.

Misses were mostly false interrupt-storm alarms on healthy cores. We kept those results and wrote the guardrails because of them.

## Real processor measurement

We read per-core scheduler delay from /proc/schedstat on the host. Idle, core 0 averaged 43 microseconds of run-queue wait per scheduling slice. With two CPU-bound tasks pinned to core 0, it rose to 1,716 microseconds, about 40 times higher, with the core at 100 percent use. One busy loop alone on an otherwise empty core did not raise the delay, so the contention scenario uses two competing tasks, a stand-in for a serving engine thread sharing a core with a noisy process. The recorded runs are copilot_run.txt and copilot_run_single_hog.txt.

## Guardrails enforced in code, not in the prompt

- Every number the model quotes must appear in the data it was given. A computed ratio is rejected and flagged for human review.
- Its diagnosis must agree with deterministic checks computed by code.
- Only one automatic action exists: lighting a locate LED. A reset can only be requested for a human to approve.
- Actions come from a fixed list and every action is written to an audit log.
- If the model call fails, a rule-based diagnoser takes over.

## Run it yourself

    pip install -r requirements.txt
    export NEBIUS_API_KEY="your-key"
    export NEBIUS_MODEL="nvidia/Nemotron-3-Ultra-550b-a55b"
    python -m silicon_tech.copilot       # emulated BMC plus real host readings
    python -m silicon_tech.bakeoff --models "$NEBIUS_MODEL" --n 60 --seed 3031
    python -m silicon_tech.audit --live  # full self-test

## Models and Nebius usage

Diagnoses use Nemotron 3 Ultra, with Nemotron 3 Super as the fallback, through Nebius Token Factory's OpenAI-compatible endpoint with the standard openai Python client. We also compared Nano and Lightning. With reasoning left on, Lightning often returned unusable answers, so its score reflects our setup, not the model at its best.

## Limitations

- No real BMC, GPU server or camera was used. The contention test ran on a small 2-core container.
- The benchmark comes from our own simulator. Real hardware will be messier.
- Even Ultra can raise false alarms on healthy cores. The guardrails and human review exist for that reason.
- A perfect score on 60 cases supports high accuracy, not certainty.
- Actions vary between runs of the same scenario.
- Diagnosis takes several seconds with a reasoning model, so the system calls the model only when the host differs from its healthy baseline.

## Feedback on Nebius and NVIDIA tools

- The OpenAI-compatible endpoint made integration fast, and the model listing call made it easy to find exact model IDs.
- Model ID naming is inconsistent across NVIDIA models (case, underscores and dots), which caused guessing.
- Reasoning models returned empty replies when max_tokens was too low. A documented minimum or a clearer finish reason would help.
- The usage page made cost tracking easy. Our whole project cost a few dollars of tokens.
