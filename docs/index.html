Measured on the Codespace running this project, from the kernel scheduler statistics in /proc/schedstat. A single busy loop on an otherwise empty core did NOT raise the delay (16.7 µs against a 9.6 µs baseline), so we use two competing tasks, a stand-in for a serving engine thread sharing a core with a noisy process.

4. What this does not show

  • The BMC is an emulator that returns standard Redfish-shaped data. No real server was connected.
  • The benchmark comes from our own simulator. Real hardware will be messier.
  • Both large models raised false "interrupt storm" alarms on healthy cores in some runs. The guardrails below exist because of that.
  • The six co-pilot scenarios are a behavior demo, not an accuracy test. Accuracy evidence is the benchmark above.
  • The contention test ran on a 2-core container, not a GPU inference server. No GPU was used.
  • Actions vary between runs. In this recording the model chose not to light the locate LED for the hot-inlet case.
